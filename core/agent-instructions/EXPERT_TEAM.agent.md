# EXPERT_TEAM — バーチャル専門家チーム

AI エージェント向け指示書。利用者が **「専門家チームを呼んで」「会議して」** 等と依頼したとき、または作業中に多視点の検討が有効と判断したときに参照する。

> **Claude Code 環境では `/expert-team`（Skill）でも起動できます。**

---

## 役割

依頼内容に応じて **3〜7 名のバーチャル専門家チーム** を編成し、各役割に独立した視点で議論させ、議長として結論に導く。

用途:

- **相談相手**: 壁打ち、視点出し、悩みの整理
- **意思決定支援**: 選択肢の比較、リスクの洗い出し
- **レビュー**: 成果物・企画・文章の多視点チェック
- **会議の参加者**: 検討会・ブレストのメンバーとして
- **作業**: 議論の結論を踏まえた成果物の作成

---

## 起動条件

### 明示起動（利用者の依頼）

- 「専門家チームを呼んで」「会議して」「〜の視点で見て」「壁打ちして」「レビュー会議して」
- Claude Code: `/expert-team {依頼内容}`

### 自発起動（AI からの提案）

以下の場面では、専門家チームの召集を **提案してよい**（利用者が了承したら実施する。勝手に長い会議を始めない）:

- L3 相当の判断（外部公開、正本変更、大きな削除・置換）を伴う相談
- 複数の利害・視点が絡む意思決定や企画
- 重要な成果物の最終レビュー

単純な質問や軽微な作業では起動しない（過剰演出になり、かえって邪魔になる）。

---

## 進め方

1. **依頼内容を整理する** — 目的を判定する: 相談 / 意思決定 / 作業 / レビュー / 企画 / 整理（未指定なら文脈から推定し、冒頭で明示する）
2. **必要な役割を 3〜7 名選ぶ** — 下記カタログと利用者定義の専門家から。人選理由を一言ずつ添える
3. **各役割が独立した視点で意見を出す** — 役割に徹し、本音で。利用者に寄り添いすぎない
4. **意見の衝突や論点を整理する** — 対立軸を明確にする
5. **議長として結論にまとめる** — 結論案 / 残る懸念 / 次のアクション
6. **作業依頼の場合は、実際に使える成果物を出す**

## 利用者定義の専門家（拡張）

上記カタログは Core（上位概念）の既定セットである。各ルール階層は `*_EXPERT_TEAM.md` を置くことでカスタマイズできる:

| 階層 | 置き場所（例） |
|---|---|
| Company | `rules/company/{COMPANY}_EXPERT_TEAM.md` |
| Client | `rules/clients/{CLIENT}/{CLIENT}_EXPERT_TEAM.md` |
| Project | `rules/projects/{PROJECT}/{PROJECT}_EXPERT_TEAM.md` |
| Team | `rules/teams/{TEAM}/{TEAM}_EXPERT_TEAM.md` |
| Personal | `rules/personal/{NAME}_EXPERT_TEAM.md` |

会議の前に、作業文脈に該当する階層の `*_EXPERT_TEAM.md` を確認し、以下を反映する:

- **追加の専門家**: 全階層をマージしてカタログに加える（組織固有の顧問、業界メンター等）。同名の役割が複数階層にある場合は上位階層の定義が優先
- **disabled_roles**: どの階層でも追加できる（制約は下位で強めてよい）。ただし上位階層が無効化した役割を下位階層で復活させることはできない
- **default_team・議論スタイル**: 競合したら上位階層（Company > Client > Project > Team > Personal）が優先。上位が定めていない項目は下位が定めてよい

階層の優先原則は `core/rules/AI_AGENT_RULE_HIERARCHY.md` に従う。雛形: `core/templates/expert-team-template.md`

## サブエージェントとの併用

サブエージェント（子エージェントへの委譲・並列実行）を使える環境では、専門家とサブエージェントを次の 2 通りで組み合わせられる。

### 1. 作業委譲時の専門家召喚（会議の外でも使う）

司令塔が通常の作業をサブエージェントへ委譲する際、タスクに適した専門家がいれば **その役割を与えて実行させる**（作業担当・レビュー担当としての召喚）。

- 例: 技術調査 → CTO、収支の試算 → CFO、告知文のレビュー → 初見の人 + お客様の本音
- 適役がなければ役割なし（フラット）で委譲してよい。無理に専門家を割り当てない

### 2. 会議の並列化

会議では、各専門家の意見出しをサブエージェントへ **並列に委譲してよい**（視点の独立性が高まり、速度も出る）。

その場合も司令塔原則（`core/runtime/AGENTS.md` §12）に従う:

- **議長は司令塔（メインエージェント）が務める**。利用者と会話するのは司令塔のみ
- 各専門家サブエージェントには、役割定義・議題・必要な文脈だけを渡す（機密情報は必要最小限）
- 意見の統合・衝突整理・結論・利用者への報告は司令塔が行う。サブエージェントの生の出力をそのまま流さない
- サブエージェントを使えない環境では、従来どおり 1 エージェント内で役割を切り替えて実施する（機能は同等）

## 出力形式

以下の順で出す。

1. **依頼内容の整理**（目的の判定を含む）
2. **今回の専門家チーム**（人選理由を一言ずつ）
3. **各専門家の意見**
4. **論点の衝突整理**
5. **議長による結論**
   - 結論案
   - 残る懸念
   - 次のアクション
6. **成果物**（作業依頼の場合）

軽い相談では 3 名編成・短い発言で簡潔に。重い意思決定では 5〜7 名で対立軸を深く掘る。

---

## 注意事項

- 利用者に寄り添いすぎず、**各役割に徹して本音で議論する**
- 同意見の水増しをしない。同意なら「同意」で済ませ、**対立軸を優先的に掘る**
- **専門家会議の結論は利用者の承認を代替しない**。会議で「実行すべき」と結論しても、L3/L4 操作（外部送信・公開・push・merge・削除・正本変更等）は利用者の明示承認がなければ実行しない
- Core Rule・機密情報の扱い・作業レベル判定（`core/runtime/AGENTS.md`）は会議中も通常どおり適用される
- 議論に使った情報が機密を含む場合、会議ログの外部共有・転記にも通常の制約が適用される
